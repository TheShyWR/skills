# session-recall

WorkBuddy 的**跨会话记忆与续接**技能（skill）。

解决一个核心痛点：多模态大模型即便有百万级上下文，真实项目里也很快耗尽；本技能把"下次会话不看到就会丢、或会重做"的上下文结构化落盘，让新会话直接接上，不必重放完整历史。

## 解决什么问题

- 上下文长度有限，长任务需要拆成多会话；
- 开新会话时，希望自动 / 可控地续接之前的进度、决策、待办、坑点；
- **区分「项目会话」与「普通会话」，并施以不同的记忆策略**——既不污染每次对话的自动上下文，又能让你在短上下文模型下续接长讨论。

## 核心设计：两类会话，记忆策略不对称

WorkBuddy 区分「任务列表下的普通会话」与「空间下的项目会话」，本技能对二者区别对待：

| 层级 | 路径 | 作用域 | 新会话加载 | 写入时机 |
|---|---|---|---|---|
| 用户级 | `~/.workbuddy/MEMORY.md` | 跨所有项目 | 每个会话自动带 | **极少**：只收长期 durable 事实（偏好 / 资产 / 通用结论） |
| 项目级 | `<项目>/.workbuddy/memory/MEMORY.md` + `YYYY-MM-DD.md` | 单项目 | 绑定项目时自动带 | **每次任务后**（工作流重要） |
| 普通会话续接区 | `~/.workbuddy/session-continuations.md` | 仅显式续接时 | **不自动带** | **仅当用户主动要求保存**（opt-in） |

设计要点：

- **项目会话自动续接**：新开项目会话直接带项目级记忆，无需口令。
- **用户级保持精简**：绝不把普通会话流水塞进去，否则会污染每一次对话的自动注入上下文。
- **普通会话的"想以后继续"需求，单独存到 `session-continuations.md`，不自动注入**，只在你说"续接 / 继续普通会话"时读取。

## 特性

- **项目会话 → 自动续接**：每次任务后整理项目级记忆，新开项目会话直接继承。
- **普通会话 → 默认不存，opt-in 双写**：你说"保存"才动笔，且同时写两份——
  - 精炼的跨项目长期事实 → 用户级（受保洁规则约束）；
  - 整场会话摘要 → 续接区（供新会话继承整段讨论）。
- **续接区滚动保留**：只留最近 10 条，超出自动 trim 最旧，不无限堆积。
- **用户级保洁**：「通用对话记忆」段超约 1500 字触发蒸馏（去重 / 合并 / 删过期），防臃肿错乱。
- **支持跨项目指定读取**：多记忆源时按需去对应项目目录读取。
- 与 `neat-freak`（洁癖）互补：日常续接用本技能，项目收尾治理用洁癖。

## 安装

将本仓库内容放到 WorkBuddy 的**用户级** skills 目录（对所有项目生效）：

```bash
# 方式一：直接克隆
git clone <本仓库地址> ~/.workbuddy/skills/session-recall

# 方式二：手动放置
# 把 SKILL.md + README.md 放到 ~/.workbuddy/skills/session-recall/
```

> 路径说明：用户级技能在 `~/.workbuddy/skills/`；项目级放在 `<项目>/.workbuddy/skills/`，仅团队共享该项目时使用。

## 使用方法

### 保存记忆（save）

在任务告一段落、准备开新会话前，说一句：

> 「存一下记忆」/「保存进度」/「记到记忆里」/「这会话有价值我要续接」

技能**先判断当前会话作用域**，再分流：

- **项目会话** → 写入 `<项目>/.workbuddy/memory/MEMORY.md` 与当日 `YYYY-MM-DD.md`（新开该项目会话会自动带）。
- **普通会话（默认不存）** → 仅当你明确说"保存 / 有价值 / 要续接"才继续，且**两份都写**：
  - **a. 精炼重要记忆 → 用户级**：agent 自行判断并提炼本会话中跨项目长期有效的事实（偏好 / 资产 / 通用结论），写入用户级 MEMORY.md 的「通用对话记忆」段（若该段不存在则创建之）；
  - **b. 整场会话摘要 → 续接区**：把整个会话的精华追加到 `~/.workbuddy/session-continuations.md`（带日期 + 主题），供新会话"续接"继承，**不进用户级**。

> 若你只是普通闲聊、没说"保存"，技能不会写任何记忆，并简短提示"普通会话默认不存，需要时说一声"。

只保留精华：关键决策与原因、目录 / 架构、已实现功能与状态、待办与下一步、踩过的坑与外部依赖。

### 续接记忆（load）

- **项目会话新开** → 项目级自动带，无需口令；说"续接"也读项目级。
- **普通会话新开** → 用户级自动带（仅 durable 事实，已精简）；普通闲聊无需续接。
- **普通会话中说「续接 / 继续上次普通会话」** → 读 `~/.workbuddy/session-continuations.md` 的最新条目，输出续接摘要（上次做到哪、当前状态、接下来、待决项）；若为空，如实说"没有可续接的普通会话，先用'保存'存一下"。

**跨项目读取**：

> 「读一下我 XX 项目的记忆」

即使当前是普通对话，也会去该项目 `.workbuddy/memory/` 读取。

## 用户级保洁规则（防臃肿 / 错乱）

用户级 MEMORY.md 每个会话都会自动注入，一旦变臃肿会污染每一次对话的上下文。因此对「通用对话记忆」段设硬约束：

- **触发**：该段内容超过约 1500 字时，下次写入前先做一次蒸馏（不必等 30 天）。
- **蒸馏动作**：去重 / 合并同类成最新态 / 删过期一次性内容 / 保留 durable 事实。
- **兜底**：蒸馏后仍接近上限，进一步压成索引式短句；细节可下沉到 `session-continuations.md` 或对应项目记忆。

## 续接区的生命周期

`~/.workbuddy/session-continuations.md` 是**跨会话共享的单文件**，所有普通会话共用，不属于任何一个具体会话。

- **生**：普通会话说"保存"，整场摘要写进去一条。
- **灭（滚动保留）**：文件最多留 **10 条**，第 11 次保存时最旧的那条被自动 trim 掉。
- **灭（手动清理）**：接上后你说"清掉已接上的旧记录"，对应条目即删。

> **重要澄清**：在 UI 里删除一个旧会话，删的是该会话自己的聊天记录，**不会**连带删除这个全局续接区文件。因此"旧的不残留"靠的是上面的**滚动保留 + 手动清理**，而不是删会话。阈值（10）可按需调整。

## 记忆的层级与作用域（再强调）

| 层级 | 路径 | 作用域 | 新会话加载 |
|---|---|---|---|
| 用户级 | `~/.workbuddy/MEMORY.md` | 跨所有项目 | 每个会话自动带 |
| 项目级 | `<项目>/.workbuddy/memory/MEMORY.md` + `YYYY-MM-DD.md` | 单项目 | 仅绑定时自动带 |
| 普通会话续接区 | `~/.workbuddy/session-continuations.md` | 仅显式续接时 | 不自动带 |

> 记忆写在磁盘上，独立于会话。删除一个会话不会丢失项目级 / 用户级记忆；续接区也不随删会话消失（见上）。只有删除整个项目目录、手动删除 `.workbuddy/memory/`、或显式清理续接区，才会丢失。

## 与 neat-freak（洁癖）的分工

- **session-recall**：日常、轻量、随时存 / 取，按作用域自动分流，保证跨会话不断档。
- **neat-freak**：项目收尾时做知识治理——对齐文档 / 规则 / 记忆与真实代码运行态，产出可被团队接手的唯一现役答案。

两者不冲突：日常续接用 session-recall，收尾治理用 neat-freak。

## 注意事项

- `.workbuddy` 是项目数据，**不是缓存**，不要当临时文件清理。
- 记忆文件不复制密钥、不堆流水账，用绝对日期。
- 普通会话的"保存"是 opt-in：不主动要求，技能不会写任何记忆，用户级因此长期保持精简。
