# session-recall — 跨会话记忆与续接

扮演跨会话记忆管理员。把"下次会话不看到就会丢、或会重做"的上下文，以可机读、可续接的形式落到 WorkBuddy 记忆体系。

## 两类会话与记忆存放（核心）

WorkBuddy 区分「任务列表下的普通会话」与「空间下的项目会话」，记忆策略不对称：

| 层级 | 路径 | 作用域 | 新会话加载 | 写入时机 |
|---|---|---|---|---|
| 用户级 | `~/.workbuddy/MEMORY.md` | 跨所有项目 | 每个会话自动带 | **极少**：只收长期 durable 事实（偏好/资产/通用结论） |
| 项目级 | `<项目>/.workbuddy/memory/MEMORY.md` + `YYYY-MM-DD.md` | 单项目 | 绑定项目时自动带 | **每次任务后**（用户习惯，工作流重要） |
| 普通会话续接区 | `~/.workbuddy/session-continuations.md` | 仅显式续接时 | **不自动带** | **仅当用户主动要求保存**（opt-in） |

关键设计：
- 项目记忆**自动续接**——新开项目会话直接带，不用口令。
- 用户级**保持精简**——绝不把普通会话流水塞进去，否则会污染每一次对话的自动注入上下文。
- 普通会话的"想以后继续"需求，单独存到 `session-continuations.md`，**不自动注入**，只在你说"续接 / 继续普通会话"时读取。

## 何时使用
- 用户说「存一下记忆 / 保存进度 / 记到记忆里 / 这会话有价值我要续接」。
- 用户说「续接上次 / 接上之前的会话 / 继续普通会话 / 上次做到哪了 / 读一下我XX项目的记忆」。
- 项目任务告一段落（用户习惯每次整理）。
- 不用于纯编码 / 调试 / 闲聊 / 项目收尾治理。

## 流程 A：保存（save，按作用域分流）

1. 判断当前会话作用域：能否定位 `<项目>/.workbuddy/memory/`（即是否为项目会话）。
2. **项目会话 → 存项目级（每次任务后）**：
   - 读现有 `<项目>/.workbuddy/memory/MEMORY.md` 与今天 `YYYY-MM-DD.md`（无则创建）。
   - 提取精华（关键决策与原因、目录 / 架构 / 技术栈、已实现功能与状态、待办与下一步、坑与外部依赖），追加到今日日志；稳定事实同步进 `MEMORY.md`（去重，不堆第二套真相）。
   - → 新开该项目会话会自动带，实现"续接"。
3. **普通对话 → 默认不保存**（防止用户级臃肿 / 错乱）：
   - 仅当用户明确说"保存 / 有价值 / 要续接"才继续；否则不写任何记忆，简短告知"普通会话默认不存，需要时说一声"。
   - 继续时**两份都写**：
     a. **精炼重要记忆 → 用户级**：agent 自行判断并提炼本会话中跨项目长期有效的事实（偏好 / 资产 / 通用结论），写入用户级 MEMORY.md 的「通用对话记忆」段（精选，不堆流水账；该段超 ~1500 字触发蒸馏；若『通用对话记忆』段不存在则创建之）。
     b. **整场会话摘要 → 续接区**：把整个会话的精华（做了什么、结论、待决项、关键上下文）追加到 `~/.workbuddy/session-continuations.md`（带日期 + 主题），供新会话"续接"继承。**不进用户级**。
   - **续接区滚动保留**：只保留最近 N 条（默认 10），超出自动 trim 最旧；用户说"清掉已接上的旧记录"时删除对应条目。旧会话在 UI 删除后，其续接记录不会无限堆积（注：`session-continuations.md` 是跨会话共享的单文件，不随某个会话的 UI 删除而自动消失，靠滚动保留 / 显式清理控制体积）。
4. 简短汇报写了什么、落哪个文件、哪个作用域。

约束：不复制密钥、不复制大段代码 / 文档原文；用绝对日期；不写流水账。

## 用户级保洁规则（防臃肿 / 错乱）

用户级 MEMORY.md 每个会话都会自动注入，一旦变臃肿会污染每一次对话的上下文。因此对「通用对话记忆」段设硬约束：

- **触发**：该段内容超过约 1500 字时，下次写入前先做一次蒸馏（不必等 30 天）。
- **蒸馏动作**：
  - 去重：合并相同或高度相近的条目；
  - 合并：把分散的同类事实（如多次更新的资产 / 偏好）收敛成一条最新态；
  - 删过期：移除一次性、已失效、或仅对某一短暂上下文有用的内容；
  - 保留：长期 durable 的偏好、资产、通用结论。
- **类比**：项目记忆靠「30 天日志蒸馏进 MEMORY.md」；用户级改为**靠体积触发**，因为它常驻注入、更怕涨。
- **兜底**：蒸馏后仍接近上限，进一步压成索引式短句；细节可下沉到 `session-continuations.md` 或对应项目记忆。

## 流程 B：续接（load，按作用域）

1. **项目会话新开** → 项目级自动带，无需口令；用户说"续接"也读项目级。
2. **普通会话新开** → 用户级自动带（仅 durable 事实，已精简）；普通闲聊无需续接。
3. **普通会话中说「续接 / 继续上次普通会话」** → 读 `~/.workbuddy/session-continuations.md` 的最新条目，输出续接摘要（上次做到哪、当前状态、接下来、待决项）；若为空，如实说"没有可续接的普通会话，先用'保存'存一下"。继承后用户可说"清掉已接上的旧记录"以修剪该条目。
4. **跨项目指定** → 用户说「读一下我XX项目的记忆」→ 去该项目 `.workbuddy/memory/` 读取（即使当前是普通对话）。
5. 若对应记忆缺失或为空，如实说明，建议先做 save。
