# steel-man

WorkBuddy 的**双向钢铁人论证法**技能（skill）。

把用户抛来的判断 / 决策 / 立场型问题先撑开、再逼问、最后才下判断——避免模型一上来就给一份看似有理、实则没戳中真问题的答案。

## 解决什么问题

- 用户常把没想清楚的问题直接丢过来：表面问"A 还是 B"，真实目标是别的东西；
- 模型容易立刻给结论、顺着用户的表述走，既不挑战隐含前提，也不摆出有力反对理由；
- 钢人法（把自己最有力的对手理由也讲透）能把问题想透，但需要一个固定流程防止跑偏。

本技能提供一套固定协议：先重构真问题，再做双向钢人论证，再逼出一个最关键的问题，等用户回答后才给明确判断。

## 触发场景

- 判断型 / 决策型 / 立场型问题："该不该 / 要不要 / 值不值 / 我是不是应该…"、"我有个想法…"、"帮我看看这个方案"、"X 和 Y 哪个好"。
- 触发词："用钢铁人论证""帮我论证一下""钢人一下""帮我钢一下"。
- **不触发**：纯事实查询（"XX 的读音""今天几号""这个函数怎么写"）。

## 协议（第一轮 → 等用户回答 → 第二轮）

### 第一轮：四步钢人论证

1. **重构真问题**：用最完整、最有力的方式重述用户真正想解决的问题（表面问法 + 背后目标 / 焦虑 / 利益 + 隐含默认前提）。
2. **双向钢人论证**：
   - 支持（钢人版）：把用户自己可能没说全的好理由补到最完整；
   - 反对（钢人版）：站在最聪明反对者立场，给出最难反驳的理由；
   - 证据边界护栏：每条辩护标清"建立在什么事实上"，依赖未证实假设 / 缺失数据 / 可疑来源的，紧跟【证据缺口：…】，防止把薄弱想法包装得逻辑自洽却事实悬空。
3. **分歧与关键变量**：点出双方真正在争什么，以及哪 1–3 个变量一旦明确会让结论翻转。
4. **一个最关键的问题**：只问一个、且能真正改变结论的那个；若缺失信息能从文件 / 数据 / 最小探针直接验证，则直接验证，不拿它当问题抛回。然后停止，等用户回复。

### 第二轮：明确判断

用户回答后给：判断（明确结论）+ 理由（短而硬）+ 下一步行动（1–3 步）。

## 铁律

- 第一轮绝不给结论。
- 反对论证必须是真钢人（你真心认为最有力的版本），不是稻草人。
- 关键问题只能有一个。

## 安装

将本仓库内容放到 WorkBuddy 的**用户级** skills 目录（对所有项目生效）：

```bash
# 方式一：直接克隆
git clone <本仓库地址> ~/.workbuddy/skills/steel-man

# 方式二：手动放置
# 把 SKILL.md + README.md 放到 ~/.workbuddy/skills/steel-man/
```

> 路径说明：用户级技能在 `~/.workbuddy/skills/`；项目级放在 `<项目>/.workbuddy/skills/`，仅团队共享该项目时使用。

## 注意事项

- 本技能聚焦"决策挑战"（二选一 / 多选一），不负责开放探索、不枚举多个方向。
- 用绝对日期，不堆流水账。
