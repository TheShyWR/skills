# deep-thinking

WorkBuddy 的**深度思考协议**技能（skill）。

把用户抛来的问题先"拆开"再"逼问"——多数问题背后的前提、信息和目标都没说全，直接答只会产出一份谁都能套用的通用建议。本技能先用四维拆解剖开问题，再逼出一个最关键的问题，等用户回答后才给最终答案。

## 解决什么问题

- 用户常把模糊、前提未明的问题直接丢过来，要的不是通用模板，而是贴合他真实目标的解答；
- 模型容易顺着表面表述立刻给答案，跳过隐含假设、缺失信息和常见认知坑；
- 需要一套固定协议，强制先把问题想透，再下结论。

## 触发场景

- 任何用户提出、需要认真应对的问题，尤其是决策型、模糊需求型，或他明确说"别给通用答案"的场景。
- 触发词："深度思考""深度分析""先别急着答""帮我先想清楚""别给我通用建议""我想认真捋一下"。
- **不触发**：纯事实查询（"XX 怎么读""今天是几号"）。

## 协议（第一轮 → 等用户回答 → 第二轮）

### 第一轮：四维拆解 + 一问

1. **隐含假设**：列出问题里用户没明说、但已默认成立的前提；若其中任一不成立，问题本身需要重问。
2. **缺失的关键信息**：列出还缺哪些信息，并说明每条一旦明确可能如何改变答案（若 A 是 X，答案偏向…；若 A 是 Y，答案翻转…）。
3. **最常见的错误**：指出人们处理这类问题时最常犯的一个错误（认知偏差、偷换目标、过度泛化等），具体到会怎么坑人。
4. **一个最关键的问题**：只问一个、且能真正改变最终答案的那个。然后停止，等用户回复。

### 第二轮：最终输出

用户回答后综合四维拆解 + 新给信息，输出：结论（明确直接）+ 为什么（紧扣真实目标，短而硬）+ 下一步（1–3 步，若需行动）。

## 铁律

- 第一轮绝不给最终答案。
- 关键问题只能有一个。
- 用户回答前不预判、不剧透结论。

## 安装

将本仓库内容放到 WorkBuddy 的**用户级** skills 目录（对所有项目生效）：

```bash
# 方式一：直接克隆
git clone <本仓库地址> ~/.workbuddy/skills/deep-thinking

# 方式二：手动放置
# 把 SKILL.md + README.md 放到 ~/.workbuddy/skills/deep-thinking/
```

> 路径说明：用户级技能在 `~/.workbuddy/skills/`；项目级放在 `<项目>/.workbuddy/skills/`，仅团队共享该项目时使用。

## 注意事项

- 本技能聚焦"把问题想透再答"，不套通用模板。
- 用绝对日期，不堆流水账。
